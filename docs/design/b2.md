# B2 — covariate forecasting experiment

B2 reuses B1 formulation B: direct four-week forecasting with supplied-final
flags, the six existing histories, and the same final outcomes and objective.
An additional masked covariate history conditions every independently fitted
target or pathogen component. There is no auxiliary nowcast objective.

The [completed B2 screen](../results/B2-screen/index.md) contains the rankings,
heatmaps, fan plots and diagnosis of source timing and training support.

## Covariates and interpretation

The completed first-pass suite is `B2-screen`: eight covariate sets (none, each
of the four groups alone, both claims, both wastewater, and all four groups),
crossed with both anchors and both input modes, using seed 42 only. This gives
32 runs, 96 season fits and 432 component fits. Cross-source pairs and all
three-group subsets are omitted. The full `B2-covariates` factorial remains
available but is not the active launch.

This is an exploratory screen: one seed does not estimate training-seed
variability, and omitted combinations cannot establish interaction effects.
The Wednesday wastewater support limitation below still applies. Execution
uses both patron nodes with eight workers per GPU; H100 concurrency is an
initial choice, not a measured optimum, and mixed hardware may produce small
numerical differences.



Four independently selectable groups produce ten numerical series; the
[Kinsa group](#kinsa-only-experiment-b2-kinsa) adds an eleventh, with its own suite:

| Group | Series | Reason for inclusion |
|---|---|---|
| `inpatient` | Flu and COVID inpatient claims percentages | Explicit requested comparison, despite weak incremental evidence in the preliminary analysis |
| `outpatient` | Flu and COVID outpatient claims percentages | Earlier care-pathway signal with comparatively fresh reporting |
| `ww_wval_like` | Flu, COVID, RSV wastewater `wval_like` | Uncapped activity level based on exponentiated group-standardized log concentration |
| `ww_pct_rank` | Flu, COVID, RSV wastewater `pct_rank` | Within-group percentile rank, aggregated with unweighted medians; stronger flu/RSV associations than wval_like in the saved comparisons |
| `kinsa` | Weekly mean of Kinsa's national daily cough/cold/flu share | Thermometer symptom signal, national only; added after the screen for its own experiment |

The two wastewater choices are from
[Wastewater, candidate indices](../data/wastewater.md), restricted to the original six candidates explicitly selected by the user.
`pct_rank` is bounded by 0 and 1; `wval_like` is not capped at 1. The latter can be flat when most sites are at their measurement floor; percentile rank supplies a less magnitude-sensitive alternative, although it cannot recover variation absent from the measurements. `robust_z` loses groups with zero IQR, while the flow-population and population-weighted candidates add panel/weighting changes that are unnecessary for this first comparison.
Neither is the official CDC WVAL. PopHIVE is excluded. The exploratory
correlations/adjusted R² in the source analysis are not held-out forecast evidence.

Each source enters with its observed availability mask. Missing history is not
zero activity. Dates and locations are aligned to B1; claims use the native
trailing-seven-day percentage on Saturday, not a sum of overlapping daily
percentages. Units and source vintage beginnings are recorded with the
[B2 dataset](../data/b2.md).

## Information states

The experiment crosses two modes, applied to both the original histories and
the covariate histories:

1. **Finalized:** finalized historical inputs in fitting and evaluation. This
   is a retrospective information-rich benchmark.
2. **Wednesday:** the Wednesday conditioning state in fitting and evaluation,
   respecting actual covariate report times. Both modes score final outcomes.

The user explicitly confirmed Wednesday evaluation inputs with final outcomes
for the second mode. Natural reporting delays remain visible through missing
cells. No fabricated 18-day wastewater release schedule is used. Observations
with historical reference dates do not establish that they were available at
those historical forecast origins.

The final-vintage designation means latest eligible values at the pinned data
cutoff, not a guarantee the publisher will never revise them again. Covariate
normalization is fitted inside the training partition. Inner validation and
held-out weeks are masked in covariate context as in the six original channels.
A covariate/location never seen during fitting must remain disabled at prediction
time rather than activate untrained input weights.
Normalization averages observed origin/history cells, so a week repeated in
multiple training windows receives repeated weight. It does not borrow a
normalizer or fitted support from other locations. Each component recomputes
these statistics after retaining episodes with its own supervised targets.
Wednesday mode retains B1's
existing supplied-final/history policy for the original six channels; the new
covariates use native source vintages.
For source eligibility, the publisher's `report_time` is the availability clock;
retrieval time and auxiliary pipeline-processing timestamps are preserved as
provenance, not substituted for it. This assumes the publisher's historical
archive dates correctly describe its intended vintages, including backfills.
Wastewater indices are source-level derived features: their within-site
baselines/ranks use the samples visible at each source vintage, independently
of the model's season partition. The finalized benchmark can therefore use
index baselines informed by later observations. Only the model's additional
covariate centering/scaling is fitted within each component's training
partition. These are retrospective comparisons, not a claim that finalized
indices were historically available.

## Model recipes and screen design

| Anchor | Fits | Masking | Epoch cap | Patience |
|---|---|---|---:|---:|
| Target MLP · B · gap-only | Six separate target fits, each receiving all selected inputs | 50% of episodes; gap only | 100 | 30 |
| Pathogen MLP · B · mixed | Three pathogen fits, each receiving all selected inputs | 50% of episodes; recent/gap/outage mixture 50/30/20 | 300 | 30 |

Other settings are inherited from the B1 recipes: 12-week history, width 64,
latent width 16, fourth-root admissions, logit ED proportions, calendar,
population/geography, dynamics, batch size 8, learning rate .001, 128 training
draws and 256 validation/evaluation draws. The source scores 0.939 and 0.941
come from [different saved comparisons](../results/b1-overnight/index.md), and
do not establish equivalence between the anchors.

The completed screen crosses eight subsets with both anchors and both modes:
**32 configurations × seed 42**, each with three held-out seasons. This is
96 configuration/seed/fold fits and 432 independently fitted target/pathogen
components; epoch selection and refit are separate fitting stages. The eight
subsets are none, the four individual groups, both claims, both wastewater,
and all four groups. The full 16-subset, three-seed factorial is available as
`B2-covariates` but was cancelled in favor of this screen.
The empty subset is a matched B2 no-covariate control in every recipe/mode.
Comparisons should be paired to those controls on identical scoring support.
Missing covariates never remove evaluation tasks.

The native NWSS archive starts on **2026-02-25**, within the 2025–2026
season. Under the unchanged three-season leave-one-season-out protocol, the
2025–2026 evaluation fold has no earlier-season Wednesday wastewater training
support; the two older evaluation folds precede wastewater vintage availability.
Consequently the Wednesday arm cannot establish a learned wastewater benefit
on these held-out seasons. Its wastewater subsets remain explicit availability
controls, while the finalized arm can assess historical associations. A later
evaluation season or a separately specified within-season protocol would be
needed to assess an operational Wednesday wastewater benefit. This limitation
does not apply automatically to claims, whose native vintages begin earlier.

The existing manager, dispatcher and frozen Hub scorer serve B2. Natural,
recent-gap and outage stress exports retain B1's original-channel masking
semantics; these are not independent claims/wastewater outage experiments.

## Kinsa-only experiment (B2-kinsa)

`B2-kinsa` tests the national [Kinsa cough, cold and flu signal](../data/kinsa.md)
(`pophive_kinsa_ili`, taken from PopHIVE) on its own. It crosses the two anchors
with both input modes and two covariate sets, `none` and `kinsa`, using seed 42
only: 8 runs, 24 season fits and 108 component fits. The `none` cells are the
`B2-screen` controls with identical scenario strings, rerun here so that each
comparison is matched within one experiment. The other four groups are not
combined with Kinsa.

Assumptions:

- **National only.** Kinsa exists for the US alone. Its channel is available at
  the `US` location and masked at all 51 state locations by native geography;
  nothing is broadcast to states or filled. Model weights are shared across
  locations, so the Kinsa input is trained and used on US cells only, and states
  can respond only through the shared weights. The state scores therefore test
  spillover, not a state signal. The channel is trained when the US has fitting
  support and is disabled otherwise, exactly as for any covariate.
- **Weekly value.** The mean of the seven daily values in a Sunday to Saturday
  week, in native percent, on the Saturday that ends it. A week has a value only
  when all seven days are visible. The channel is normalized like every
  covariate, inside the training partition.
- **Vintages are PopHIVE Git commits.** A daily value is available from the date
  of the first commit containing it (day resolution, the same rule as the other
  covariates); a Wednesday origin sees each day's latest such value. No release
  lag is assumed. PopHIVE's history begins **2026-04-06**, so no Wednesday origin
  earlier than that has any Kinsa value.
- **Wednesday arm.** Consequently the Wednesday arm has no shared support in any
  of the three leave-one-season-out folds (zero refit support when 2025-26 is
  held out; zero evaluation support when either older season is). It cannot show
  a Kinsa effect. It is an availability control, and its `none`-vs-`kinsa`
  difference measures run-to-run and initialization variability: the extra input
  changes the first layer's initialization even when the input is always masked.
  Only the finalized arm can assess an association. Its dataset flag makes the
  values retrospective: PopHIVE has held them since 2026-04-06 and no value has
  ever been revised.
- **One seed.** A single seed cannot estimate training variability; the
  Wednesday-arm difference is the only noise estimate in this experiment and is
  itself one draw.

The dataset gained an eleventh covariate, so `build_b2.npz` was rebuilt with the
ten earlier channels bit-identical; see the [B2 dataset](../data/b2.md#kinsa-national-only).
The `B2-screen` and `B2-covariates` suites are defined over the original four
groups and are unchanged.

## Prepare, run and postprocess

The completed experiment is `B2-screen`. Build instructions are in
[B2 data](../data/b2.md). The following records its manager plan and training
launch; do not re-plan the completed experiment or submit duplicate active jobs.
Use a new experiment name for a changed data/model protocol.

```bash
cd /proj/jlessler/projects/tapestry-all/tapestry
.venv/bin/python -m tapestry.models.manager plan -e B2-screen --suite B2-screen --seeds 42 --retrospective --device cuda
LANES=8 GPUS=6 sbatch --job-name=B2-screen --array=0-3 --nodelist=g1803jles01 scripts/jlessler.sbatch B2-screen
LANES=8 GPUS=6 sbatch --job-name=B2-screen --array=0-1 --nodelist=g1803jles02 scripts/jlessler.sbatch B2-screen
.venv/bin/python -m tapestry.models.manager status -e B2-screen
srun -p jlessler --cpus-per-task=4 --mem=30G --time=10:00:00 --nodelist=g1803jles02 .venv/bin/python -m tapestry.models.manager rank -e B2-screen
```

`plan` saves canonical scenarios, runnable Python sources, input hashes and
design. Training and full postprocessing use that source snapshot. The shared
queue uses eight workers per GPU across both nodes; this concurrency is an
execution choice, not a measured B2 optimum. `status` prints a resubmission
command for unfinished work; check Slurm before resubmitting.

The postprocessing launcher ranks, regenerates the compact heatmaps and numeric
tables, and runs the full EpiBench comparison with two scoring workers. It
requests four CPUs, 30 GiB RAM and ten hours on `g1803jles02`.

```bash
sbatch scripts/b2_postprocess.sbatch
.venv/bin/python -m tapestry.models.manager status -e B2-screen
```

For documentation-only updates, use the already saved ranking tables:

```bash
.venv/bin/python scripts/plot_b2_screen.py --ranking docs/results/B2-screen/ranking --output docs/results/B2-screen
.venv/bin/python scripts/audit_b2_support.py
.venv/bin/python -m mkdocs build
```

The [results page](../results/B2-screen/index.md) owns the interpretation;
plotting does not overwrite it. Full forecasts and per-task EpiBench scores
remain in the Longleaf experiment folder. Its local documentation mirror
contains primary score tables, the secondary rankings/provenance and 72 SVGs.

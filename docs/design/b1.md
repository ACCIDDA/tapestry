# B1: Wednesday vintages and masked inputs

B1 retains B0's MLP, convolution, multiscale, sharing and spatial formulations.
It predicts reference finals for two completed weeks, then four future weeks
from each sampled correction. The default fits six independent targets;
pathogen-grouped and shared six-target fits are also available. Every component
receives all six observed histories and shares parameters across locations.

## Precomputed data

Like B0, training reads a compressed NumPy dataset, without querying providers or
the explorer. B0 stores one finalized `[week, channel, value/mask, location]`
panel. B1 stores each Wednesday's actual historical information state:

| Array | Axes |
|---|---|
| `X_values`, `X_available` | episode, 12 context weeks, 6 channels, 52 locations |
| `Y_recent`, `Y_recent_valid` | episode, 2 recent weeks, 6 channels, 52 locations |
| `Y_future`, `Y_future_valid` | episode, 4 future weeks, 6 channels, 52 locations |
| `X_provenance`, `X_reason` | same as X |
| `Y_provenance`, `Y_reason` | episode, 6 output weeks, 6 channels, 52 locations |

Issuance dates, exact context/target dates, ordered locations and JSON metadata
are saved alongside the arrays. Missing values use zero storage with a false mask;
a true observed zero has a true mask. Training and inference zero hidden values
before transforms, anchors, or derived features. The pinned label arrays are
separate from historical input arrays. Labels never replace historical inputs.

```bash
uv run python -m tapestry.model_data build-wednesday \
  --data-root data --start 2023-08-09 --end 2026-09-16 \
  --truth-cutoff 2026-09-16 \
  --output data/processed/build_b1_wednesday.npz

uv run python -m tapestry.models.b1_report \
  --dataset data/processed/build_b1_wednesday.npz \
  --output data/processed/b1-audit
```

This reads `SelectedData.selected_tables`, canonical Hub time-series products,
and native unsmoothed Delphi archives. It does not read the plotting cache.
Sources must already be acquired locally. The materializer retains snapshot IDs,
source paths, release timestamps, manifest hashes, missingness reasons and the
selector's quarantine audit. Those are metadata, never model inputs. A cell's
integer provenance index refers to the saved metadata table; a Delphi entry
stores the fallback reason `absent_hub_historical_coverage`.

## Calendar and source assumptions

- The requested July 30, 2023 and November 5, 2023 are interpreted as **week
  starts**, giving first supported Saturday ends August 5 and November 11.
  The latter restriction applies to RSV ED inputs and labels, not other channels.
- Native Hub event dates and Delphi weekly `reference_time` are treated as week
  ends. The reader requires Saturdays and rejects other weekdays, rather than
  shifting dates heuristically. Current local records passed this check. Hub
  Parquet schemas may expose `target_end_date` despite a catalog `date` alias;
  both are supported explicitly.
- For Wednesday issuance `d`, `s=d−4 days`. Context ends at `s`; outputs are
  `s−7, s, s+7, s+14, s+21, s+28 days`. Offsets from the following Saturday are
  `[-2,-1,0,1,2,3]`. November 22, 2023 therefore predicts finals for November 11
  and 18, followed by November 25 and December 2, 9 and 16.
- The date-based cutoff includes all of Wednesday. Timestamps normalize to UTC;
  naive timestamps are assumed UTC. This follows the explorer's end-of-day
  convention and **does not establish availability before an intraday deadline**.
  Retrieval dates never substitute for missing historical release dates.
- Admissions remain counts. Hub ED observations are proportions. Delphi ED
  percentages are divided by 100. Only native states/DC and US are retained;
  no geographic aggregation, interpolation or filled Delphi variants are used.
  Delphi `fill_method=source` is the native observed series.
- Resolve the latest eligible **complete Hub `as_of` snapshot per source**, and
  independently resolve each Delphi observation's latest eligible `report_time`.
  Thursday information is excluded from Wednesday inputs, even when on disk.
- **Conservative coverage assumption:** for each channel/location, the earliest
  observation in any eligible Hub snapshot establishes coverage from that week
  onward. Absent earlier periods may use Delphi. Interior holes, trailing gaps,
  explicit nulls, conflicts and disappearances in later snapshots remain missing.
  This deliberately avoids resurrecting a retraction through an older release or
  Delphi. It can retain missingness where archive coverage cannot be distinguished
  from a provider omission. No later release establishes earlier Wednesday coverage.
- Reference finals are the latest eligible revisions under the same Hub-first
  policy at the explicitly supplied truth cutoff. They are not guaranteed
  immutable. Genuine source support gaps remain false masks; no synthetic labels.
- All issuance rows are retained for auditing. Episode iteration skips rows with
  no conditioning data or no permitted labels; inference does not require labels.
  Incomplete initial contexts are allowed and padded with false masks.

## How many training samples are lost?

Measured on September 16, 2026, using the saved dataset and its September 16
reference-truth cutoff. An **episode** is one Wednesday issuance containing all
six channels and 52 locations. A missing channel, location, or input week does
not by itself remove an episode. The current iterator removes an episode only
when there are no inputs anywhere, or no labels within the requested partition.
These counts precede artificial training dropout.

### Whole episodes

| Comparison | Finalized-input baseline | Wednesday-input B1 | Lost |
|---|---:|---:|---:|
| Full B1 requested period, August 9, 2023–September 16, 2026; two recent + four future outputs | 163 | 156 | **7 (4.3%)** |
| Actual short-run fitting partition through May 28, 2025; labels also bounded by that date | 95 | 88 | **7 (7.4%)** |
| B0 September start, same four-future-week task and current local source snapshots | 157 | 154 | **3 (1.9%)** |
| B0 September start, four-future-week task, fitting origins and labels through May 28, 2025 | 90 | 87 | **3 (3.3%)** |

The first two rows hold B1's reference-final source policy, dates, labels and
support fixed, and substitute finalized histories as a counterfactual input
panel. This isolates missing historical availability. All seven removed
issuances are **August 9, 16, 23, 30 and September 6, 13, 20, 2023**. They have
reference labels but no eligible Wednesday inputs in the local archives.

The B0 comparison starts with the original builder's September 1, 2023 lower
bound, so only **September 6, 13 and 20** are lost. It uses a fresh reconstruction
of B0's direct CDC panel from local snapshots, not the absent original frozen
B0 experiment dataset. CDC snapshot IDs and file hashes are in the numerical
audit. Its source policy differs from B1's Hub/Delphi policy, so the first two
rows are the cleaner measurement of vintage availability alone. Both comparisons
use 12-week context and the same location order. The full-period counts describe
eligible development episodes, not a claim that all of them were used for fitting.

B1 has 156 eligible six-output episodes but only 154 with future labels at the
end of the archive: two trailing episodes have recent-final supervision only.
Likewise, the fitting partition has 88 six-output episodes and 87 future-output
episodes. These boundary differences must not be mistaken for data losses.

Dropping the seven episodes removes **8,534 labeled output cells** from
281,840 otherwise eligible cells (3.0%), or from 161,720 in the short-run fitting
partition (5.3%). Grouping by issuance/target/location with at least one label
instead gives **1,460 local target examples** lost out of 48,289 overall or
28,009 in that fitting partition. Output cells repeat observation weeks across
origins/horizons; neither count represents independent epidemic samples.

### Missing inputs inside the windows

Whole-episode loss is modest, but incomplete conditioning is substantial.
Against the **same B1 reference-final support**, **156,782 of 556,296 input cells
(28.2%)** lack an eligible Wednesday value. In the earlier short-run fitting
partition, this is **143,903 of 307,632 (46.8%)**.

| Channel | Finalized input cells, full period | Unavailable Wednesday | Full period missing | Fitting partition missing |
|---|---:|---:|---:|---:|
| Flu admissions | 94,988 | 17,831 | 18.8% | 27.7% |
| COVID admissions | 97,796 | 39,660 | 40.6% | 68.8% |
| RSV admissions | 80,372 | 23,775 | 29.6% | 58.6% |
| Flu ED | 95,420 | 28,296 | 29.7% | 45.9% |
| COVID ED | 98,228 | 27,963 | 28.5% | 45.9% |
| RSV ED | 89,492 | 19,257 | 21.5% | 35.9% |

An input cell is one issuance/context-week/channel/location. The same observation
week is counted each time it appears in a different 12-week window. Denominators
include all candidate windows, including the seven discarded ones; they exclude
cells missing even in reference finals, pre-support padding and unsupported RSV
ED weeks. They do not include artificial dropout. No Wednesday-only cells were
found outside the reference-final support in this audit. Unknown historical
availability, delayed reporting and conservative missing/retraction handling all
contribute; these totals do not attribute every missing cell to one cause.

Labels for an unavailable input channel are **retained** whenever the episode has
other conditioning data. For example, 60 retained supervised episodes have no
COVID-admissions history anywhere in the 12-week context, and 61 have no
RSV-admissions history. B1 still learns those outputs using other channels,
calendar/geography and its learned missing-history baseline. The 28.2% input
missingness therefore does not mean 28.2% of training episodes were discarded.

The reproducible breakdown, per-channel counts, definitions and source hashes
are in [the training-support audit](b1-training-support.json). Recompute with:

```bash
  --b0-dataset data/processed/b0_latest_for_b1_support_audit.npz \
  --output docs/design/b1-training-support.json
```

The optional B0 comparison file was built with
`build_dataset('data', start='2023-08-05', end='2026-09-12')` from
`tapestry.model_data.finalized`, then saved under the shown path. The audit applies
B0's September start itself. Omit `--b0-dataset` to compute the matched B1
finalized-versus-Wednesday counts without rebuilding B0. Changed raw snapshots,
cutoffs or fitting boundaries can change these counts.

## Model formulations

The successful B0 formulations are available through named presets and explicit
architecture switches. These are **B0-derived candidates for B1**, not evidence
that their B0 ranking will hold with Wednesday inputs and sampled nowcasts.

| Preset | Encoder | Independently fitted groups | Spatial exchange | Output-head sharing |
|---|---|---|---|---|
| `target_mlp` (default) | MLP | Six targets | None | Shared within component |
| `pathogen_mlp` | MLP | Three admission/ED pathogen pairs | None | Shared within component |
| `target_conv` | Two temporal convolutions | Six targets | None | Shared within component |
| `target_multiscale` | Multiscale temporal convolutions | Six targets | None | Shared within component |
| `spatial_conv` | Convolution | All six together | Shared context attention | Shared |
| `joint_mlp` | MLP | All six together | Joint location/target attention | Per pathogen |

Independent-target/pathogen MLPs and independent-target multiscale correspond
to the leading B0 results. The joint-attention MLP with pathogen heads was also
among the leading configurations. Convolution and shared spatial convolution
are retained as useful contrasting B0 formulations, not claimed B0 winners.
Standalone presets default to cap 100, except `joint_mlp` cap 300 matching that
B0 reference. A multi-preset comparison uses a **common training budget** from
its base configuration (default cap 100); `--epochs 300` changes it for all.

The implementation reuses B0's convolution/multiscale encoders, spatial block,
transforms, loss scales and scientific weights. It supports:

- `--encoder mlp|conv|multiscale_conv` and `--fit-partition target|pathogen|all`.
- `--spatial none|attention|pathogen_spatial|target_spatial|joint_location_target`.
- `--decoder legacy|residual2`, `--head-sharing shared|pathogen|target`, and
  `--heads shared|state_us`.
- `--noise global|local` (local adds a per-location latent), plus
  `--us-error none|shared_factor`. Recent and future stages have independent
  draws; validation freezes global, local and national noise separately.
- Admission transforms `sqrt|fourth_root|log1p`; ED transforms
  `linear|logit|fourth_root`. Scores always remain in native units.
- Calendar, geography and dynamics switches; location embeddings; lookback,
  width, latent size, learning rate, weight decay and training/stopping budgets.

The failed stochastic-trend decoder stays removed. Raw/rate-only admissions
remain excluded following the B0.1 design. The default uses width 64, latent 16,
fourth-root admission rates per 100,000 and logit ED inputs. Adjacent slopes and
acceleration are recomputed after masking with validity flags. B1 continues to
exclude observation-age and release-age/revision-history features.

Population denominators remain fixed across seasons. Checkpoints save the
mapping and population-file hash. The default is B0's frozen
`data/metadata/b0_locations.csv`; a different CSV can be supplied explicitly.
A shorter `--lookback` crops the precomputed context before scale fitting and
masking. A longer one requires materializing at least that many weeks; the
runner rejects insufficient context rather than synthesizing it. Episodes with
no conditioning observations in the selected context are excluded before fitting.

Each output has its own focal-history encoding and explicit recent-anchor and
any-history flags. Visible preliminary values anchor their corresponding recent
corrections. Missing values use the last visible focal value, or a learned
context baseline when that history is entirely missing. Positive transformed
outputs use B0's softplus residual with a .001 normalized anchor floor; ED uses
a sigmoid for linear/logit inputs or a bounded inverse fourth-root transform.

Every forecast receives the original masked Wednesday encoding and **only its
own target's paired two sampled recent values**, including in grouped fits.
Member `m` always feeds member `m`; no averaging, shuffling or teacher forcing.
Forecast gradients pass through the sampled corrections. Shared components can
represent within-group dependence through their shared noise. Separate fitted
components use independent draws; common member numbering across them does not
represent learned dependence. Marginal scores do not establish joint calibration.

## Scenario strings and masking controls

B1 uses complete, round-trippable `b1:v2:` strings using B0's field vocabulary,
extended with pipeline and masking settings. Example, obtained with
`python -m tapestry.models b1 scenario --preset target_conv --mask-rate 0.25`:

```text
b1:v2:h12:tr_4rt:ed_logit:geo1:dyn1:lw_obj:enc_conv:sp_none:hd_sh:dec_leg:nz_glob:us_none:z16:w64:ep100:pat30:bs8:m128:lr0.001:hs_sh:cal1:id0:fit_targ:vm256:wd0.0:pipe_two:mask0.25:mr0.5:mg0.3:mo0.2
```

`enc_conv` selects convolution, `fit_targ` independently fits six targets,
`pipe_two` selects the two-stage model, and `mask0.25` masks 25% of episodes in
expectation. All architecture switches, training settings and masking settings
are encoded; no omitted fields silently become defaults when parsing a string.
Floating-point values round-trip without truncation. Seeds, data snapshots and
date partitions are recorded separately in the run manifest, as in B0.

Use `--preset target_conv` to start from a readable preset, or `--scenario 'b1:v2:…'`
to load an exact configuration. Explicit flags override either base and the
**resolved** string is saved in the checkpoint and manifest. Changed settings
produce a different identifier. Output folders use a readable short `run_id`
plus a 12-character digest of the complete string, avoiding filesystem name-length
limits. The full string is also included in per-cell score files and the
comparison manifest. `B1Scenario.from_string` and `.flags()` support programmatic
round trips and invocation.

`--mask-rate p` is the probability an episode receives an artificial missingness
pattern, **not the fraction of individual cells hidden**. `0` preserves natural
missingness only; `.5` is the original B1 default; `1` assigns every episode a
pattern, which may overlap already-missing inputs. Conditional pattern fractions
are controlled by `--mask-recent`, `--mask-gap`, and `--mask-outage`; they must sum
to one and default to `.5/.3/.2`.

| Mask rate | Natural | Recent reports | Local gap | Channel outage |
|---:|---:|---:|---:|---:|
| 0 | 100% | 0% | 0% | 0% |
| .25 | 75% | 12.5% | 7.5% | 5% |
| .5 | 50% | 25% | 15% | 10% |
| 1 | 0% | 50% | 30% | 20% |

These probabilities are assumptions for experiments, not optimized choices.
They apply to fresh masks for each component and epoch; they do not alter labels
or scientific weights. Both direct and two-stage models accept any masking rate
in single-model training. The comparison grid uses an unmasked direct control.

Three masks are distinct:

```text
A = naturally available Wednesday inputs (precomputed)
D = artificially hidden available inputs (drawn every training epoch)
V = A & ~D (the only mask seen by the network)
```

Default episode probabilities are 50% natural, 25% missing recent reports, 15%
local gaps, 10% source outage. These are configurable starting assumptions:

- Recent reports hide one or two ending weeks, across all locations. Half choose
  one channel; half choose the entire admissions or ED family.
- A local gap hides one random 1–3 week block in one location/channel history.
- An outage hides one channel across all context weeks and locations.
- `D` intersects `A`; no artificial flag is supplied to the network. All-hidden
  histories remain possible and exercise the learned baseline.

Packed training D arrays are saved for each epoch and fitted component in `masks-*.npz`,
with shape and issuance order. Validation D arrays are saved explicitly. A is
recoverable from the pinned dataset; V is their Boolean difference. Validation
uses fixed masks and latent draws, with separate generators from training.
Natural/two-stage controls use natural validation; masked B1 uses a fixed draw
from its training-mask mixture. Inference defaults to natural availability;
the Python API accepts explicit dropout, and the CLI exposes reproducible stress
scenarios. Masked older inputs do **not** create a historical reconstruction loss:
supervision is still two recent finals plus four future weeks.

## Fitting and prediction

For each fitted component, minimize one-half the weighted recent native-unit
fair CRPS plus one-half the weighted future native-unit fair CRPS. Each task
is independently normalized over its valid cells. Fitting-only unique-label-week Q95 scales and
B0 season/geography weights are retained (equal target-date seasons, 80% states/DC,
20% native US, renormalizing absent geography groups). Fixed cell weights are
computed before dropout; masks never redefine scientific supervision weights.
B0 target coefficients `[1,1,1,.5,.5,.5]` apply within shared or pathogen-grouped
fits and cancel within single-target fits. They would still be needed in a
combined six-target selection score; reports expose per-target diagnostics. A completely unsupported target
raises an error rather than yielding an untrained component.

Input scales use only fitting Wednesday histories: the latest **permitted
fitting-episode** vintage for each context date, counted once. Native loss scales
use unique permitted reference-label dates. Validation does not refit scales.

```bash
uv run python -m tapestry.models b1 train \
  --train-end 2025-05-28 \
  --validation-start 2025-06-04 --validation-end 2025-07-30 \
  --retrospective --preset target_conv --mask-rate 0.5 \
  --output data/experiments/b1-masked/s42

uv run python -m tapestry.models b1 predict \
  --checkpoint data/experiments/b1-masked/s42/model.pt \
  --issuance 2025-08-06 --members 256 \
  --output data/experiments/b1-masked/s42/predictions.npz
```

The defaults are a 100-epoch cap, patience 30, 128 training members, 256 fixed
validation members, Adam at .001 and no weight decay. Components use seed + 10000*i.
Each component retains its best validation checkpoint; `--patience 0` instead
retains the final epoch of a fixed-budget fit. The runner performs
**no final refit** on validation data. Prediction NPZs contain the paired six-week
samples, quantiles, exact dates, A/D and input/training provenance. They are native
research artifacts, not Hub submissions; a Hub exporter must select only that
Hub's supported horizons.

The fitting/validation split is chronological and labels are bounded by target
date independently of context. `validation_end` is the effective model-fit cutoff
because stopping uses that partition. Later pinned truth requires the explicit
`--retrospective` flag. For an operational backtest, build the fitting dataset with
`--truth-cutoff` no later than the model-fit cutoff and no later issuance rows;
use a **separate** later-pinned `--evaluation-dataset` for scoring. This prevents
unavailable later training labels from silently entering an operational claim.

### Named experiments and cluster launch

B1 uses the **same manager and shared dispatcher as B0**:
`list → plan → run/dispatch → status → rank → compare`. The standalone
`b1 compare` command remains useful for small local comparisons. For the cluster,
use named experiments so completed seeds are reused and interrupted/failed
attempts are retained.

From the repository root, after copying the pinned Wednesday NPZ and
`data/metadata/b1_locations.csv`, plan the cross:

```bash
.venv/bin/python -m tapestry.models.manager plan -e B1 --suite B1 \
  --epochs 300 --patience 50 \
  --mask-rates 0 0.25 0.5 --seeds 42 43 44 \
  --train-end 2025-05-28 \
  --validation-start 2025-06-04 --validation-end 2025-07-30 \
  --evaluation-start 2025-08-06 --evaluation-end 2026-07-29 \
  --retrospective --device cuda \
  --frozen data/evaluation/b0_hub_comparison_q23

mkdir -p output/slurm
LANES=4 GPUS=4 sbatch --array=0-3 scripts/b1_jlessler.sbatch B1

.venv/bin/python -m tapestry.models.manager status -e B1
.venv/bin/python -m tapestry.models.manager rank -e B1
sbatch scripts/b0_compare.sbatch B1
```

`--frozen` enables B0's ensemble-relative forecast benchmark on the matched
subset. Omit it when frozen Hub inputs are unavailable: all-six-target native
forecast **and nowcast** scoring/ranking still run. The default B1 suite has
six formulations × (direct/unmasked, two-stage mask rates 0/.25/.5), three seeds:
**24 configurations, 72 seed runs, 276 component fits**. The default manager
budget is 300 epochs/patience 50, 128 training members and 256 validation/evaluation
members. `--presets` selects fewer formulations; full `b1:v2:` strings can be
passed through the manager's `--scenario` option for other crosses.

The 300-epoch cap applies equally to controls and masked variants. Fresh masks
are drawn each epoch; extra epochs allow more combinations but are not evidence
that every model needs them. Positive patience selects the best validation
checkpoint. B1 has no final refit on validation data.

`plan` writes the usual `experiment.json`, `jobs.csv`, `design.json`,
`preflight.json`, and `code/` source snapshot. It pins input hashes. Do not refresh
that snapshot while workers run. A changed data/date/evaluation setting requires
a new experiment name, avoiding accidental reuse of scores from a different
protocol. Code versions/source hashes remain provenance; the manager warns about
mixed commit states. Configuration/seed attempts live at
`<run_id>/s42/attempt-001/`, with `run.json`, `run.log`, and a `b1/` directory
holding the model, native scores, saved quantiles/masks and optional Hub scores.
The full canonical string remains in manifests/CSVs; the shorter `run_id` avoids
filesystem component-length limits. `status` rebuilds `runs.csv` from attempts.

Each GPU allocation runs multiple lanes from the same shared queue, as B0.1.
Seeds of one configuration stay sequential; different configurations share a GPU.
The user-selected range is **4–6 processes per GPU**, default `LANES=4`.
The launcher allocates six CPUs (one thread per process), so `LANES=6` needs
no CPU override. Across six patron GPUs this provides 24–36 worker slots.
The current 24-configuration cross can have at most 24 active seed runs because
seeds of one configuration remain sequential, as in B0.1.
This range and the two-day walltime are resource choices, not measured B1
capacity/runtime guarantees. For all six patron GPUs, submit both arrays
with the same `GPUS=6`:

```bash
LANES=4 GPUS=6 sbatch --array=0-3 scripts/b1_jlessler.sbatch B1
LANES=4 GPUS=6 sbatch --array=0-1 --nodelist=g1803jles02 scripts/b1_jlessler.sbatch B1
```

After checking `squeue -a`, resubmit the launcher to resume interrupted work.
Use `--retry-failed` after the experiment name to requeue failed seeds. Resume is
at the complete scenario/seed boundary, not optimizer state. New tasks/seeds are
reconciled into the existing dispatch queue. For a local allocation or debugging,
`manager run -e B1 --fit-workers 4 --keep-going` uses the same attempt records.
B1's full-budget GPU memory/throughput remains to be measured at four and six
processes per GPU; B0.1's measured concurrency does not establish B1 capacity.

**Protocol assumption:** this preserves B1's chronological retrospective split:
fitting through May 28, 2025, validation June 4–July 30, 2025, evaluation August 6,
2025–July 29, 2026. The short summer validation window is a limitation for
respiratory-season selection. Reusing the manager does not silently adopt B0's
three-season leave-one-season-out CV or its later-season fitting data.

### Forecast and nowcast ranking

`manager rank` and `manager compare` use completed attempts and refuse incomplete
experiments unless `--allow-incomplete` is explicit. They create hashed
`ranking-…/` and `comparison-…/` folders, respectively, without refitting.
Both write `configuration_ranking.csv`, `run_scores.csv`, `target_scores.csv`,
and a definition/provenance manifest. `compare` also writes merged native
summaries and graphs. Primary native rankings use natural inputs; recent/gap/
outage stress scenarios each have their own rankings.

Score columns follow B0's naming. `config_id` identifies the configuration (the
readable B1 `run_id`) and `scenario_string` carries its full `b1:v2:` string,
matching B0's `config_id` convention. The `stress` column is the **evaluation
input scenario** (`natural`, `recent`, `gap`, `outage`), not a model setting;
configurations are ranked against each other within one `stress` and `task`.

The `task` column separates **nowcasting** (offsets -2/-1: final values of the
two recent completed weeks) from **forecasting** (offsets 0–3). Direct controls
have no nowcasting output and no nowcasting rank. Missing Wednesday inputs do
not remove a score when reference truth exists. Both tasks retain fair CRPS,
23-quantile WIS, WIS dispersion/underprediction/overprediction, median absolute
error, and 50/80/90/95% coverage in per-cell scores. B1 reuses B0's exact
`quantile_scores` implementation for these quantile metrics.

The native overall selection score for each task is **fair CRPS divided by the
fitting-only channel/location Q95 scale**, with the existing scientific weights:
equal target-date seasons; admission targets weight 1, ED targets .5; states/DC
80% equally across supported states, native US 20%; missing geography groups
renormalize. Eligible origins/horizons average within a location. Each task
normalizes to total weight one independently. Configuration ranks use mean seed
scores and report sample SD (undefined for one seed). Normalized WIS is also
reported. This is a normalized predictive-error objective, not ensemble-relative
skill. Exact cells, truths, scales and weights must match across configurations
and seeds; missing support cannot produce an easier ranking.

### Reused Hub scoring and EpiBench comparison

When `--frozen` is supplied at planning, each seed's scoring step matches natural
B1 **future** quantiles to the B0 frozen tasks by target, reference Saturday,
target-end date, location and horizon. Reference Saturday is the Saturday after
Wednesday issuance, with horizons 0–3; recent offsets are never relabelled as
Hub forecasts. ED stays in proportions; admissions retain quantile rounding.
`hub-support.json` records frozen and matched counts for every case.

On this narrower subset, candidate and official ensemble are both scored against
**the same frozen Hub observations**. These can differ from B1's pinned reference
finals; the native report stays separate. The Wednesday information state also
differs from the original Hub submission cutoff, so this is a retrospective
benchmark, not an operational submission comparison. No matching Hub task removes
an observation from the native six-target scores.

`manager rank` reuses B0's location-relative WIS aggregation under `hub-ranking/`:
80% states/DC, 20% US; admission weights 1/ED .5 within season; equal seasons;
mean/SD across seeds. Exact matched dates/truth/reference forecasts must agree
across runs, not just task counts. If no tasks match, the report says so explicitly.

`manager compare` additionally reuses the full B0 **EpiBench config scorer**, R
scoringutils, Hubverse exporter, diagnostic plots and projection fans, against
that matched subset. The cluster's existing `scripts/b0_compare.sbatch B1` loads
R and invokes the common manager. EpiBench's separate all-target comparison
ranking uses B0's equal-target geometric WIS-ratio convention; it is not the
native normalized-CRPS rank or the manager's arithmetic Hub rank. Outputs are
named `hub-epibench-scores.parquet`, `hub-leaderboard.csv`, `hub-run-ranking.csv`,
`hub-configuration-ranking.csv`, `hub-plots/`, `hubverse/` and `epibench/`.
Pinned mirrors containing the frozen commits, EpiBenchmark and R dependencies
are required for this optional comparison. The existing B0 docs publisher and
B0 season-CV calibration/mixture tools are not adapted to B1 artifacts.

Without `--presets`, compare uses the resolved single preset/scenario and all
explicit overrides. With `--presets`, those names determine encoder, spatial
exchange, output-head sharing and fit grouping; all use the common training
budget and other settings. Conflicting single-preset/architecture flags are
rejected rather than silently ignored. The grid defaults to rates `0,.25,.5`;
`--mask-rates` supplies an explicit list, while a single `--mask-rate p` requests
rates `0,p`. A single-model pipeline is selected with `train --pipeline direct`
or `train --pipeline two_stage`; compare deliberately expands both pipelines.

The same episodes and labels are scored under natural, recent-report, local-gap
and channel-outage evaluation scenarios. Their fixed stress masks are identical
across configurations for each seed/issuance and use the common lookback; training
mask rates do not change evaluation masks. Recent comparisons include only the
two-stage configurations, while future comparisons include all configurations.
A support audit rejects missing model cells. Prediction uses only natural masks
unless the caller supplies `--stress-scenario recent|gap|outage`.

Outputs include per-cell CRPS/WIS/50%/95% coverage Parquet files; summaries by
target, target season, horizon and states/DC versus US; source usage and
missingness CSVs; preliminary-versus-reference-final plots; paired sampled paths;
and score/coverage graphs. WIS uses the existing 23-quantile grid and rounded
admission quantiles. Scores are in native units; Hub-relative scores require the optional matched
benchmark described above. The forward chronology
alone does not make a later-truth development run prospective.

### Scoring when a Hub benchmark is unavailable

Hub forecast availability does **not** determine whether a target can be scored.
B1's direct scorer uses the reference-label validity mask, independently of
whether a corresponding Hub forecast, ensemble or historical Hub challenge exists.
Reference labels may come from Hub observations or the permitted Delphi fallback.

| Available data for a target/date/location | Evaluation |
|---|---|
| Reference observation, no matching Hub forecast | Native-unit CRPS, WIS and 50%/95% coverage; retain the task |
| Reference observation and matching Hub forecast | Direct scores remain valid; the optional frozen-Hub benchmark adds matched forecast skill |
| No reference observation | No score for that cell; report missing label support |

The existing B1 scorer already evaluates all six targets independently, including
flu/COVID/RSV ED proportions, and both recent-final weeks and all four forecast
horizons. It compares the B1 variants on identical eligible cells. An ED score
measures ED prediction; it does not substitute for an unobserved admissions
outcome. If only ED truth is available, ED performance is still reportable and
admission performance remains unavailable. Raw admission and ED scores have
different units and should not be pooled into an unnormalized overall score.
Hub-relative comparisons report their narrower matched support separately
instead of dropping non-Hub cells from the direct-score report.

**Scoring is implemented and has run.** The local one-epoch comparison produced
`data/experiments/b1-smoke/summary.csv`, per-cell `scores-*.parquet` files and score/
coverage graphs. Its summary contains all six targets, three model variants,
four natural/missingness scenarios, and CRPS/WIS/50%/95% coverage. For the masked
model under natural inputs, each target has 1,196 scored output cells across the
six August 6–September 10, 2025 issuances. The runs remain execution checks:
full-budget training/scoring has not run. Hub integration is exercised separately
with synthetic benchmark inputs, not used to claim model skill.

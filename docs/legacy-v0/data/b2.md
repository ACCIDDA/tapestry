# B2 model data

B2 keeps B1's six targets and adds eleven separately masked covariates:

- inpatient claims percentages for influenza and COVID-19;
- outpatient claims percentages for influenza and COVID-19;
- `wval_like` wastewater activity for influenza A, SARS-CoV-2 and RSV;
- `pct_rank` wastewater activity for the same three pathogens;
- `kinsa_ili`, the national weekly Kinsa cough/cold/flu share from PopHIVE.

`wval_like` is the uncapped magnitude index requested for this experiment. It
uses `exp((log(value) - group p10) / group sd)`. `pct_rank` is its bounded,
distribution-free companion. The saved wastewater comparison found percentile
rank materially smoother than `wval_like` and particularly useful for the
floor-heavy influenza and RSV series. Together they test magnitude and robust
within-site position without introducing a new index definition for B2.

## Dataset contract

The final-outcome and finalized-input cutoff is pinned to **2026-09-16**.

`data/processed/build_b2.npz` contains every B1 archive array plus:

| array | axes | meaning |
|---|---|---|
| `X_finalized_values`, `X_finalized_available` | issuance, history week, B1 channel, location | B1 reference-final history reconstructed from B1 final outcomes and explicitly final-filled cells |
| `C_final_values`, `C_final_available` | issuance, history week, covariate, location | latest real covariate revision through the B1 truth cutoff |
| `C_wednesday_values`, `C_wednesday_available` | issuance, history week, covariate, location | latest real revision published on or before that Wednesday |

`B2Dataset.episodes(input_mode="finalized")` uses the finalized original-six
history and finalized covariates. `input_mode="wednesday"` uses B1's Wednesday
history policy and Wednesday covariates. Both modes use the same reference-final
outcomes. Covariates are returned as `C[history_week, covariate, value_mask,
location]`; zero is a valid observation and is distinct from the mask.

The Wednesday B1 history policy is unchanged: context older than two weeks is
reference-final, while the latest two weeks use eligible Wednesday reports and
flagged final fallback. Thus “Wednesday” in B2 means B1's established
retrospective input recipe, not a fully operational reconstruction of every old
history week.

## Wastewater derivation and vintages

Raw concentration revisions are the registered `delphi_nwss` archive. Versioned
state/laboratory metadata are the registered `delphi_nwss_aux` archive. The
builder publishes `derived_nwss_state_indices` through `RawDataRepository`; the
explorer discovers that source through the ordinary catalog and selection path.

At every native report time, the builder resolves the latest concentration and
auxiliary revision no later than that report. It also excludes samples dated
after the origin. Group baselines and eligibility use only that information:

1. group by sewershed, NWSS source, PCR target and contemporaneous major lab method;
2. require 26 distinct sample weeks and nonzero log-value standard deviation;
3. calculate `wval_like` and empirical `pct_rank` within each group;
4. mean samples within group-week, median groups within site-week, then median sites within state-week;
5. require three sites; construct the US series with the same unweighted site reduction.

Every derived report time is stored as a complete state. Explicit null rows
invalidate cells that disappear, so retractions or eligibility loss are not
silently carried forward. `n_sites` remains in the derived artifact for audit;
it is not a model covariate or an explorer series.

The Delphi NWSS archive service begins **2026-02-25**. Dates before that are
unavailable in the Wednesday arm; the builder never applies the former 18-day
synthetic delay or backfills a vintage. The exact first usable publisher vintage
in the selected archives is recorded in the derived manifest and B2 metadata.
North Dakota has no finite selected NWSS index in this archive and remains
masked for all six wastewater covariates. Guam appears in the raw derived
artifact but is outside B1's 52-location panel. B2 does not impute, broadcast,
or substitute either geography.

Claims use native `report_time` revisions. The selected local archives begin
**2020-05-29** for all four selected signals. A null, invalid value, or
same-release conflict is an explicit unavailable revision and supersedes an
older value. State and native national rows are used; no geographic aggregation
or broadcasting is performed.

## Kinsa (national only)

`kinsa_ili` is built from the registered `pophive_kinsa_ili` snapshot (see
[Kinsa (PopHIVE)](../../data/kinsa.md)). Its daily values become one value per Saturday: the
mean of the seven daily values of the Sunday to Saturday week, in native percent
of users. The week's value is rebuilt at every real report date, using each day's
latest report on or before it, and exists only once all seven days are visible.

Kinsa has no state rows. Its channel holds values for `US` and nothing for the
51 states, so it is unavailable there **by native geography** and stays masked;
the builder never broadcasts, fills or substitutes it, and the metadata records
`covariate_native_geography` (`nation` here, `state+nation` for the rest). The
existing per-location covariate arrays and masks carry this without a change to
the model: a channel with no fitting support at a location is disabled there at
prediction. Weights are shared across locations, so the Kinsa input is fitted on
US cells only.

Report times are the PopHIVE Git commit dates, which begin on 2026-04-06. The
Wednesday arm therefore has no Kinsa value for any earlier origin, and the
first-vintage support is recorded in `covariate_vintage_starts`. No release lag is
modelled.

## Build

**Historical (pre-2026-09).** The `tapestry.model_data build-b2-nwss` step that built `derived_nwss_state_indices` was removed in the 2026-09 restructuring (commit 4a0b172; recover it from git history). `tapestry.dataset.build` reads the existing derived snapshot; there is currently no command to rebuild it. `build-b2` was replaced by
`python -m tapestry.dataset.build build` (one `panel.npz`, see
[the unified design](../../design/restructure-2026-unified.md) §3). The commands
below are kept as the record of how B2 was built:

```bash
.venv/bin/python -m tapestry.data --data-root data pull pophive_kinsa_ili
.venv/bin/python -m tapestry.model_data build-b2-nwss --data-root data

.venv/bin/python -m tapestry.model_data build-b2 \
  --base-dataset data/processed/build_b1_wednesday_calendar.npz \
  --data-root data \
  --output data/processed/build_b2.npz
```

The raw and derived manifests, input hashes, B1 dataset hash, truth cutoff,
per-covariate first vintage and coverage counts are embedded in the saved
metadata.

Claims retain Delphi's native percentage scale; a value such as `0.25` means
0.25%, and is not divided by 100. `wval_like` is positive, dimensionless and
unbounded. `pct_rank` lies in `[0, 1]`. Each index baseline is computed within
its own publisher vintage, independently of the later model fold. The model's
feature scaling is then learned from observed training episodes only. In the
finalized arm, the final publisher vintage's index baseline can therefore use
observations later than a held-out model season; this is part of that arm's
explicit retrospective-final information condition.

## Decision log

- 2026-09-20: chose `wval_like` plus `pct_rank` from the six already analyzed
  NWSS indices. This replaced an intermediate `log_mean`/`frac_above` proposal
  before the B2 experiment was launched.
- 2026-09-20: required real signal and auxiliary archive states. Snapshot
  last-set times and modelled availability are not accepted as Wednesday
  vintages.
- 2026-09-20: kept `n_sites` as audit support rather than adding an eleventh
  model input.
